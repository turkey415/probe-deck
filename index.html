Game servers

Found on the LAN

Asks the LAN for game servers, like the game's own server browser.

What good looks like

On a tournament LAN, the probe to the server should see: ping under 2 ms (amber up to 5), jitter under 1 ms, no loss, no spikes, and full-size packets passing. One CS2 tick is 15.6 ms (64 tick), so jitter is also shown in ticks. "Server reply" is the game's own query (A2S over UDP): it includes the time the server takes to answer, so it runs a little above ping. Perf-Deck nodes get the same tests without a game server: "App reply" is Perf-Deck's own UDP ping, answered by the app on that PC, the closest stand-in for a game client's packets.

    Stop the browser warning

    A self-signed certificate is encrypted like any other, but browsers warn because nobody vouches for it. Trust it once on each PC:
    Windows (Chrome, Edge): download it, open the .crt, Install Certificate → Local Machine → Place in Trusted Root Certification Authorities.
    Linux: sudo cp probe-01.crt /etc/pki/ca-trust/source/anchors/ && sudo update-ca-trust (Fedora/Nobara), then restart the browser.
    Firefox: Settings → Privacy & Security → Certificates → View Certificates → Authorities → Import.
    Check the SHA-256 fingerprint above matches what the browser shows before you trust it.

    Walk the VLANs
    
    
    
      
      
    
      
    
      
    
    
    
  
    
  
    
    
    How it works
    
    
      
      
    • Plug the probe into a trunk port. For each VLAN it sends tagged frames and gets a real DHCP lease.
      • 
      
    • From that address it pings the VLAN's gateway, asks its DNS servers and fetches the internet check URL, then releases the lease.
      • 
      
    • The probe's own address and traffic stay as they are. On an access port no VLAN answers.

    How it works
    
    
      
      
    1. Press Start surveying, then walk the hall and plug the probe into each seat's jack, in order.
      2. 
      
    2. On each jack it waits for the switch port (CDP/LLDP), an address and its checks, then saves the seat and moves to the next label (B-14 → B-15). On PoE it boots on every jack; that's fine.
      3. 
      
    3. The T-Display Probe Viewer and this page show the next seat. Plugging into the same port again within 10 minutes isn't counted twice.
      4. 
      
    4. Each seat gets good, check or bad, with why: not gigabit, half duplex, no DHCP, slow DHCP, gateway loss or latency, DNS, internet, an unusual VLAN, or a port shared with another seat.
      5.
